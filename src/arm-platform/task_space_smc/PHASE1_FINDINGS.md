# 阶段 1 实测发现：6 关节实机的正运动学 / 零位校验

> 日期：2026-08-02
> 硬件：A-L1-GAMMA 6 关节实机，`/dev/ttyUSB0`，位置模式
> 工具：`task_space_smc/fk_gravity_verify.py`、`merge_fk_verify.py`

本文记录实测数据和踩过的坑。**很多结论只有通过重复测量才能发现**——单次
测量拟合得再好都不构成证据，这是本轮最贵的教训。

---

## 1. 已确证的硬件事实

全部来自 `/dev/ttyUSB0` 的被动抓包（只读，未发送任何字节），2480 帧零校验错误。

### 1.1 协议

```text
0xFE 0xAA | cmd | len | payload | sumCheck | addCheck    PC -> 板
0xFE 0x55 | cmd | len | payload | sumCheck | addCheck    板 -> PC
```

| cmd | 方向 | 内容 | 速率 |
|---|---|---|---|
| `0x10`/`0x11`/`0x12`/`0x13`/`0x14` | 下行 | position / velocity / **力矩** / kp / kd，各 7×f32 | 按需 |
| `0x20`/`0x21`/`0x22`/`0x24` | 上行 | position / velocity / current / temperature | **200.6 Hz** |
| `0x23` | 上行 | voltage，**全通道恒为 0，固件未实现** | 2.0 Hz |
| `0x01` | 上行 | 心跳，payload 单字节 `0x1b` | 20.0 Hz |
| `0x25` | 上行 | 未知，payload `[1,1,1,0,0,0,0]` (int32) | 2.0 Hz |

`0x01` 和 `0x25` 原先被 `DecodeFrame` 的 switch 静默丢弃。现已实现心跳计数与
`IsLinkAlive()`；`0x25` 只统计不解释（含义需固件方确认）。

### 1.2 `0x12` / `0x22` 的单位是 Nm

由量化步长反解，四条全部落在干净整数上：

| 量 | 实测 LSB | 反解 | ratio |
|---|---|---|---|
| position | 3.833771e−04 | 16 bit / ±4π rad | 0.99969 |
| velocity | 2.441788e−02 | 12 bit / ±50 rad/s | 1.00016 |
| **力矩 J1–3** | 1.367378e−02 | 12 bit / **±28.00 Nm** | 0.999996 |
| **力矩 J4–6** | 2.930164e−03 | 12 bit / **±6.00 Nm** | 1.00016 |

两种电机标度不同且分别对应各自峰值力矩（`motor_config.yaml` 的 27.0 / 5.5，
固件取整到 28 / 6）。若是安培，没有理由让两个不同品牌电机的量程恰好落在
各自峰值力矩附近。

**这只证明了反馈方向 `0x22`。命令方向 `0x12` 仍是强推断，需台架验证。**

### 1.3 第 7 通道是幽灵数据

固件按 7 通道上报（`dataLen=28`），但实物只有 6 个电机：

| 流 | joint1–6 范围 | 通道 7 |
|---|---|---|
| position | −1.381 … 1.324 | **−6.5231 rad**（超出 ±4 限位） |
| velocity | −0.208 … 0.159 | **+27.9731 rad/s**（超 RS05 上限 5.6 倍） |
| temperature | 27 … 31 °C | **1** |

屏蔽手段：`arm_config.yaml` 的 `a_l1_gamma6` 只声明 6 个关节，驱动层便不会
读第 7 通道。回归测试见 `test/test_arm6_config.cc`。

### 1.4 传感器分辨率

```text
位置 LSB 3.834e-04 rad  ->  末端约 0.13 mm (六关节 RSS)
速度 LSB 2.442e-02 rad/s ->  末端约 10 mm/s
```

项目指标 RMS < 1 mm 可达（约 8 倍余量），但**仿真那个 0.0097 mm 比传感器
分辨率还低 13 倍，物理上无法在真机复现**。

## 2. 控制链的硬约束

| 约束 | 值 | 出处 |
|---|---|---|
| 反馈速率 | **200.6 Hz** | 固件上报速率，非带宽限制（上行只用了 26.8%） |
| 位置模式控制频率 | **≤ 100 Hz** | `ArmPlatform::ExecuteControlCycle` 对 `dt < 0.01` 抛异常 |
| 力矩模式控制频率 | ≤ 200 Hz | 无软件限制，受反馈速率约束 |
| 位置环 kp | 30 / 5 | `student_arm_node` 默认 `p_gain` |

**原 SMC 基线的 500 Hz 在真机上不成立**——一半周期拿不到新反馈。

### 2.1 kp 限制的稳态下垂

承受重力的关节必然有稳态误差 `τ_重力 / kp`：

```text
joint2 承受 2.2 Nm，kp=30  ->  下垂 0.073 rad（实测 0.0857~0.1859）
```

这不是故障，但它污染了几乎所有基于"标称位姿"的计算，见第 3 节。

### 2.2 超时保持会棘轮式抬升承重关节

`ControlLoop` 在命令超时后用 `last_known_position_`（**已下垂的位置**）作为
新的保持目标，于是每次命令流中断就再下垂一次：

```text
joint2 实测: 1.3235 -> 1.4860 -> 1.5661 -> 1.6371 -> 1.8038   (上限 2.0)
```

**这是共享代码的固有行为，未修改。** 规避方式：每次实验前显式 `--goto`
到已知位姿，不依赖"上次停在哪"。

## 3. 方法论踩坑记录

按发现顺序。每一条都在实机上付出了时间代价。

### 3.1 安全检查里没有任何几何约束（代价：撞桌）

原检查只有关节限位、力矩预算、单步跨度。joint4 的测试位姿需要
`joint1 = -1.5 rad`，把整条臂绕基座轴甩下 86°，j3–j4 那段主臂压在桌面上。

**已修**：新增桌面碰撞约束。桌面在 `z=0`（与基座安装面同高），只存在于
`x < 20mm` 一侧（`joint1` 转轴指向 +x，那侧是桌沿外的空区）。

余量取 **80mm** 而非 30mm，两个原因：

- `desk_violations` 只采样关节原点和末端，电机壳与线缆的实际外形低得多
  （实测点采样只报侵入 11mm，实物却整条压在桌面上）
- 要覆盖 kp 下垂（计划点最低 z=+19mm，实际掉到 +0.4mm，差 18.6mm）

### 3.2 分步移动预先切好路径（代价：扫描误中止）

`move_through` 原本一次算好整条路径再逐点下发。机械臂有跟踪滞后（实测最大
0.1859 rad），预算好的第 k 个点与滞后后的实际位置可能超过 `MAX_STEP`，
于是一次完全正常的移动被判为违规。

**已修**：`plan_next_step()` 每步从当前实际位置现算，按构造恒等于 MAX_STEP。

### 3.3 参考相位用标称位姿（代价：joint3 两次差 2.243°）

参考力矩用 `SWEEP_PLAN` 里的标称位姿计算，但机械臂因下垂停在别处，且下垂
量每次不同。相位对其余关节的位置极其敏感：

```text
joint2 下垂 0.05 rad  ->  joint3 表观零位漂 2.865°
joint2 下垂 0.09 rad  ->  漂 5.157°
```

**已修**：`model_reference_measured()` 用每点的实测完整关节角算参考，
且 `run_sweep` 现在记录全部 6 个关节的角度（原来只存被扫的那个）。

各关节受影响程度（位姿误差贡献 vs 力矩噪声 1σ）：

| 扫描 | 位姿误差 | 噪声 1σ | 谁主导 |
|---|---|---|---|
| joint1 | −0.007° | 0.0294° | 噪声 |
| joint2 | +0.087° | 0.0611° | 相当 |
| joint3 | **+4.096°** | 0.1116° | **位姿 37×** |
| joint4 | −0.148° | 0.3677° | 噪声 |
| joint5 | **−5.141°** | 0.0793° | **位姿 65×** |

### 3.4 摩擦滞回破坏双向平均（代价：joint2 两次差 9.407°）

双向平均本应消掉库仑摩擦，但它要求正反两次的摩擦**对称**。扫描的第一个点
破坏了这个前提：机械臂是从转移过来的，最后一次运动方向由转移决定。

诊断信号：`Δτ/Δq` 在每一点都精确等于 **−kp**，证明正反差异是位置环产生的
摩擦滞回。而双向半差的分布形态不对——从 0.866 Nm 单调衰减到 0.02，
**库仑摩擦应该量级大致恒定**。

**已修**：`approach()` 每个测量点先过冲 `APPROACH_OVERSHOOT = 0.15 rad`
再退回，保证测量前最后一次运动方向恒定，摩擦变成被拟合常数项吸收的同号偏置。

### 3.5 到达新位姿后的首扫被污染（根因）

**这是最重要的一条，只有重复测量能发现。**

joint2 三连跑：

```text
Repeat 1   φ = 5.023°   b = 0.3568      <- 到达位姿后的首扫
Repeat 2   φ = 9.746°   b = 0.6782
Repeat 3   φ = 9.753°   b = 0.6740
```

剔除首扫后两遍吻合到 **0.007° = 0.11σ**，比声称的精度还好。

历次 joint2 测量回顾，模式完全一致：

| 测量 | φ | 性质 |
|---|---|---|
| 旧法(双向) 第1次 | +1.501° | 首扫 |
| 旧法(双向) 第2次 | −7.906° | 首扫 |
| 单向 上轮 | +5.614° | 首扫 |
| 单向 本轮第1遍 | +5.023° | 首扫 |
| **单向 本轮第2遍** | **+9.746°** | **热身后** |
| **单向 本轮第3遍** | **+9.753°** | **热身后** |

四次首扫散布在 −7.9° ~ +5.6°（跨度 13.5°），两次热身后差 0.007°。

物理原因推测：到达新位姿后线缆张力重新分布、齿隙落位、结构应力松弛。
**不是"采样时还在动"**——每点的 `tau_std` 都在传感噪声底以内，是跨点的
缓慢状态漂移。

**已修**：`--warmup`（默认 1）在每个位姿先跑一遍丢弃的扫描。热身数据仍写入
CSV（方向标记 `fwd_warmup`/`rev_warmup`）作为证据，但 `merge_fk_verify.py`
跳过它们。

## 4. 目前唯一站得住的结论

**几何正确。** `resid/A` 在首扫和热身后都稳定：

```text
joint1 0.0268    joint2 0.0104 / 0.0355 / 0.0318 / 0.0337    joint3 0.0389 / 0.0436
```

全部远低于 0.05 阈值。这个量对首扫污染不敏感——污染改变相位和常数项，
不破坏正弦形状。

**所以 URDF 的连杆长度与关节轴向与实物一致，可以进入阶段 2 的质量标定。**

### 尚未确定

- **全部零位偏差数值作废**，需带热身重测（包括 joint1，它的 10.616° 也是首扫）
- `ratio`（一阶质量矩比值）稳定在 **1.22~1.48**，方向明确（URDF 偏轻），
  但精确值待重测确认

### 术语澄清

重力只能测出 **一阶质量矩 `m·r`**，无法分离质量与力臂：

```text
1.00 kg × 0.100 m  =  0.50 kg × 0.200 m  =  2.00 kg × 0.050 m  ->  同一个重力力矩
```

所以 `ratio = 1.23` 的准确说法是"**一阶质量矩**比 URDF 大 23%"。把它归因于
质量，前提是力臂（几何）正确——而这正是 `resid/A` 在验证的东西。

## 6. 6 关节构型的冗余度为零

6 关节做 6D 位姿任务，雅可比是 6×6 方阵，**零空间秩为 0**。
`nullspace.kp` / `kd` / `q_nominal` 全部失效。

抽样 20000 位形的对比：

| 指标 | 7 关节 | 6 关节 |
|---|---|---|
| 秩亏比例 | 0.000 % | 0.000 %（结构上可行） |
| cond(J) 中位数 | 41.1 | 41.4 |
| cond(J) p99 | 515 | **4060** |
| cond > 1e3 占比 | 0.29 % | **3.60 %** |

典型区域几乎不退化，但**病态区域出现频率高一个数量级、程度高两个数量级**。
轨迹规划必须避开那 3.6 %。

另：末端从 `link7` 改为 `link6` 后位置前移 **91.00 mm**，已验证的 whole

## 阶段 2 实测（2026-08-02）

### `0x12` 力矩通路

| 量 | 结果 | 方法 |
|---|---|---|
| 标度 α | **0.9932 ± 0.0943**（joint1） | 启动力矩以上的位移斜率 `dΔq/dt_ff = α/kp` |
| 符号 | 正确 | 同上 |

**测法的关键**：α 只能在关节【确实在动】的区间测。摩擦只产生常数偏移，
不改变斜率，所以斜率法对摩擦免疫。kp 由重力数据独立验证（`τ_g/下垂 = 30.1`
≈ 命令值 30）。

**一个必须避免的误判**：`0x22` 反馈斜率 `dτ/dc` 不是标度。MIT 模式下
`τ_报告 = kp(p_des−p) + t_ff`，关节不动时斜率=1、自由移动时斜率=0，
它测的是「前馈有多少没被运动吸收」。实测 joint2 得 0.983、joint1 得 0.533,
差异只反映摩擦不同。若 `0x22` 报的是固件算出的指令值而非实测电流，
这个测量还是循环论证。

### 静摩擦（启动力矩）

双向启动力矩：`f = 半和`（静摩擦，可靠）、`r = 半差`（静止时未平衡残差，
受进入方向影响，不能单独当重力读数）。

| 关节 | 启动 +/− (Nm) | 静摩擦 (Nm) | 死区 (rad) | 死区 (°) |
|---|---|---|---|---|
| joint1 | 0.40~0.50 / 1.00 | 0.70~0.75 | ±0.023~0.025 | ±1.34~1.43 |
| joint2 | 2.60 / 0.90 | 1.75 | ±0.0583 | ±3.34 |
| joint3 | 0.50 / 0.80 | 0.65 | ±0.0217 | ±1.24 |
| joint4/5/6 | 0.6 Nm 内未起步 | ≥0.60 | ≥±0.12 | ≥±6.88 |

启动力矩本身有约 7~20% 的测量离散（joint1 两轮 0.40 vs 0.50），
是摩擦的固有随机性，须计入误差预算。

### ⚠️ joint4/5/6 (RS05) 在断电重启后失效

**现象**

| | 位置指令 +0.5 rad | 力矩前馈 1.5 Nm | tau 反馈 |
|---|---|---|---|
| joint1/2/3 (DM4340) | 正常响应 | 正常响应 | −0.048 / −2.865 / −0.089（随命令变化） |
| joint4/5/6 (RS05) | dq = 0.0000 | dq = 0.0000 | **+0.0015 恒定，三个完全相同** |

**这不是静摩擦。** 静摩擦挡得住运动，挡不住力矩反馈的变化 —— joint1/2/3 即使
不动，反馈也精确跟随命令（`dτ/dc ≈ 1`）。RS05 三个通道的反馈锁死在同一个
`0.0015`，像未初始化的默认值而非真实读数。

**时间点：与断电重启重合**

```text
断电前  --goto 成功移动 joint4 (-1.4955 -> 0.0033)
                        joint5 (-1.4338 -> 0.8994)
                        joint6 (-1.4991 -> 0.8077)
断电后  joint4/5/6 = 0.0034 / 0.0014 / 0.0024，此后从未动过
```

**不是力矩测试造成的**：第一条力矩指令发出在重启之后，而重启后的第一轮阶梯里
它们就已无响应。

**故障边界正好落在电机型号分界上**（DM4340 全好、RS05 全坏），指向 RS05 侧的
供电 / 使能 / 通信问题，而非软件。软件侧已排除：`DMMotor::UpdateCommand` 对所有
关节无条件调用 `SetCurrent`，无按关节分支；`rate_torque_`(RS05)=1.6 未夹掉 1.5 的
命令；`Pop()` 把 7 个通道一起打进 `0x12` 帧，而同帧的 joint1/2/3 通道生效。

**结果：再次断电重启后三个关节全部恢复**（命令 +0.5 rad，实测 +0.4968 /
+0.5052 / +0.4983，tau 也恢复正常变化）。所以是上电时序问题，重启即可解决。

**这给出一个必须固化的运行前检查**：RS05 通道有可能在上电后不建立通信，
且失效时**看起来和"静摩擦极大"一模一样** —— 位置指令和力矩指令都无响应。
唯一的判别特征是**力矩反馈锁死在同一个常数**（三个通道都是 `0.0015`）：

```text
真·静摩擦：关节不动，但 tau 精确跟随命令（joint1/2/3 的 dτ/dc ≈ 1）
通道失效：关节不动，且 tau 恒定不变
```

任何实验开始前都应先验证这一点，否则会把硬件故障误读成物理测量结果 ——
本轮就差点得出"RS05 静摩擦 ≥1.5 Nm"的错误结论。已在
`phase2_torque_probe.py` 的管路检查中覆盖（`np.ptp(taus_chk) < 1e-6` 判定为
通路故障而非标度测量）。


### 这解释了零位偏差的重复性天花板

早先从重力扫描【迟滞】估的摩擦 0.07~0.21 Nm 是**动摩擦**；标定读数取自
**静止**状态，适用的是**静摩擦**，两者差 3~10 倍（Stribeck 效应）。

单点位置不确定度 = 死区，正弦拟合多点平均按 √N 收敛：

| 关节 | 单点 | 13 点 | 31 点 | 本会话实测 |
|---|---|---|---|---|
| joint1 | ±1.34° | ±0.37° | ±0.24° | ~0.4° |
| joint2 | ±3.34° | ±0.93° | ±0.60° | 跨轮 0.385° |
| joint3 | ±1.24° | ±0.34° | ±0.22° | — |

**预测与实测同量级。** 本会话曾提出的多个假设（温度漂移、端点不稳定、
首扫污染）都是同一根因的不同表现，不需要单独建模。

**推论：前馈迭代不会带来数量级改善** —— 它压的是 kp 下垂，不是摩擦。
阶段 3 的现实目标是 ±0.4°，不是 0.1°。

### 修复的缺陷（均只在实机暴露）

| 缺陷 | 后果 |
|---|---|
| 力矩通道超时兜底发 `p=0,d=0,current=0` | MIT 模式下关节失力；0.05s 超时被扫描间隙常规触发 → 垮臂 |
| `enable_direct_effort_command` 在 launch 硬编码 `False` | 命令行传值被静默忽略，整轮实验什么都没发出去 |

### 一次实机事故

节点重启期间无指令保持，机械臂下垂压到桌面（joint3 壳体距桌面 3.4 mm，
电机只扛 1.15 Nm 而重力需 2.63 Nm，差额由桌面承担）。用 6 Nm 逐级加力脱离。
**根因是在勉强安全的位姿上反复重启** —— 应先移到高余量位姿再改代码。

## 「关节不动」的三种原因及判别（必读）

本轮实机调试中三次遇到「命令下去关节纹丝不动」，**三次原因完全不同**，
而表象几乎一样。误诊任何一次都会把硬件/配置问题当成物理测量结果写进标定。

| 观察到的现象 | 真实原因 | 判别特征 | 代价 |
|---|---|---|---|
| joint2 不动 | **静摩擦** | tau 精确跟随命令（`dτ/dc ≈ 1`） | —— |
| joint4/5/6 不动 | **RS05 通道未建立通信** | tau **锁死在同一常数**（三个通道都是 `0.0015`） | 差点得出「静摩擦 ≥1.5 Nm」，真值 0.10~0.12，**差 12 倍** |
| joint5 不动 | **节点在力矩模式，位置指令被旁路** | 跟踪误差 = 命令量，且 tau 接近零 | 浪费一次 25 分钟扫描 |

### 判别流程

```text
关节不动
  ├─ tau 跟随命令变化？
  │    是 -> 静摩擦（真实物理量，继续测量）
  │    否 -> 继续
  ├─ tau 是否恒定不变（且多个通道值相同）？
  │    是 -> 通道未建立通信，断电重启
  │    否 -> 继续
  └─ 跟踪误差是否恰好等于命令量、tau 接近零？
       是 -> 节点模式不对（位置工具 vs 力矩模式，或反之）
```

### 已固化的防护

| 工具 | 检查 | 触发时的行为 |
|---|---|---|
| `fk_gravity_verify.py` | `check_position_path_active()` | 节点若在力矩模式，**入口即拒绝启动** |
| `phase2_torque_probe.py` | `check_effort_enabled()` | 节点若在位置模式，入口即拒绝 |
| `phase2_torque_probe.py` | `np.ptp(taus_chk) < 1e-6` | 判为通路故障而非标度测量 |

三条都有回归测试覆盖。**根本教训：任何「没有响应」的观察，在归因为物理量之前，
必须先证明指令确实到达了执行器。**

## joint4/5 的一阶质量矩 ratio（阶段 3 前馈用）

### joint5 实测

| 遍次 | A (Nm) | ratio | resid/A |
|---|---|---|---|
| 1 | 0.1253 | 0.950 | 0.245 |
| 2 | 0.1164 | 0.883 | 0.265 |
| 3 | 0.1207 | 0.915 | 0.177 |
| 4 | 0.1248 | 0.946 | 0.247 |

**ratio = 0.92 ± 3.5%**（好于事前预估的 ±20% —— 21 点拟合把摩擦噪声平均掉大半）

**方向与其他关节相反**：joint1/2/3 的 ratio 是 1.22~1.45（实物比模型重），
joint5 是 0.92（实物比模型轻 8%）。在信噪比约 1 的条件下不宜过度解读，
但足以说明「用 ratio=1.0」对 joint5 有 8% 偏差。折算前馈误差仅
`0.13 × 0.08 = 0.01 Nm`，比其静摩擦 0.10 Nm 小一个数量级 —— 实用上确实无关紧要。

### ⚠️ `resid/A < 0.05` 判据在低信噪比下失效

joint5 的 `resid/A = 0.18~0.27`，远超阶段 1 的 0.05 阈值。**这不表示几何错误。**

```text
阶段 1 确立该判据时:  joint1/2/3   A = 0.89~4.23 Nm，摩擦 0.63~1.78  ->  A >> f
joint4/5 的情况:                   A = 0.13 Nm，  摩擦 0.10~0.125    ->  A ≈ f
```

`A ≈ f` 时残差由**摩擦噪声**主导而非形状误差，同一个数字不再指示几何问题。
判据只在 `A / f > 5` 左右时有效。对 joint4/5 应改看 **ratio 的跨遍复现性**
（实测 ±3.5%），而不是单遍的 resid/A。

**教训**：一个在高信噪比下确立的判据，直接搬到低信噪比场景会给出错误结论。

## 阶段 1 报告的「静摩擦」其实不是静摩擦

阶段 1 的扫描是往返双向的，并用 `stiction = 0.5*(fwd − rev)` 估计静摩擦，
得到 0.07~0.21 Nm。阶段 2 用双向启动力矩直接测，得到 **0.625~1.775 Nm**，
相差 3~10 倍。

**原因**：`approach()` 的过冲方向恒为 `+`，所以正扫和反扫的**最后进入方向
相同**、摩擦同号。双向平均既没有抵消摩擦，半差也就不代表摩擦。

实测验证（joint4 热身遍，41 对配对点）：

```text
半差 0.5*(fwd − rev) = +0.0052 ± 0.0134 Nm
真实静摩擦（阶段 2）  =  0.125 Nm
半差仅为真值的 4%
```

**两个推论**：

1. **阶段 1 的「静摩擦」列作废**，一律以阶段 2 的启动力矩为准
2. **反扫是冗余的** —— 单向进入已把摩擦固定成常数、被拟合的 `b` 项吸收。
   阶段 3 因此采用单向单遍，扫描时间减半（39 min → 19.3 min）

```text
joint1  0.0419  vs  0.176   ->  压掉 4.2 倍
joint2  0.0443  vs  0.149   ->  压掉 3.4 倍
joint3  0.0247  vs  0.036   ->  压掉 1.5 倍（本来就接近死区）
```

### ⚠️ joint4 的 ratio：窄区间的测量是错的

```text
窄区间 0.8 rad（覆盖 13% 周期）  ratio = 1.479，四遍散布 ±8.5%
宽区间 7.0 rad（覆盖 111% 周期） ratio = 0.932 / 0.943，两遍差 1.2%
```

## 环境污染：多个节点实例同时发布 `/joint_states`

排查 ROS 实时仿真发散时，真正的根因是**环境里累积了 5 个 `student_arm_node`
实例**，runner 收到的是多个独立仿真交错的数据。

### 症状与误导

```text
关节角在相邻 5 ms 步之间跳 3.9 rad     <- 物理上不可能
末端误差 324~371 mm
RViz 里模型"崩了"、连杆散开
```

看起来像控制器发散、z 轴翻转、或动力学模型错误。**实际是数据源被污染。**

### 判别特征

**任何"物理上不可能"的跳变，都应先怀疑数据源而非动力学。**
5 ms 内 3.9 rad 意味着 780 rad/s，远超关节速度上限（5.6 rad/s）——
这个矛盾在第一眼就能排除动力学解释。

辅助佐证：`ros2 node list` 出现重名警告、同名节点多次出现。

### 根因：清理失败且未被察觉

`pkill -f ...` 在本环境下返回 exit 144 但**并未生效**，进程从最早的实机阶段
一路累积到 21 个。而我每次都假定清理成功，直接启动新实例。

**教训：清理必须【验证】而不是假设。** 正确做法：

```bash
for p in $(pgrep -f "<pattern>"); do kill -9 $p; done
sleep 3
ps aux | grep -E "<pattern>" | grep -v grep | wc -l    # 必须为 0
```

这在实机上更危险 —— 残留节点会同时向真机发送指令，而它们的控制目标互不相同。
