# A-L1 Gamma 6DOF：只读反馈复查报告

本轮顺序：旧数据离线分析 → 全7槽位与源码映射检查 → 只读停止规则与回放 → 16秒真机纯接收 → 条件评估后关闭串口。**未进入控制模式，未发送控制数据。**

## A. joint5：旧窗口完整分析

最终分类：**很可能是反馈噪声/量化**。这不是对单个采样真实运动的绝对排除。

### position差分、量化、偏置、时滞与串扰

- j4/j5位置只有2个离散值，步长与峰峰值均为0.000383377rad（0.021966°）。用均匀估算时间作有限差分，dq只为0或±0.0760502rad/s。单步差分会放大量化跳变，不可当独立高精度速度传感器。
- j5净位移+0.000383377rad，但协议速度积分约+0.0465947rad；j4净位移相同，协议积分约+0.0564429rad。不能用这些速度值直接积分得到真实位移。
- 顺序按同一周期的0x20→0x21配对，以q[k+1]−q[k]为差分；j5与v[k]相关系数−0.27575，与v[k+1]为+0.26184。j4分别−0.23386/+0.23645。扫描±10帧没有强一致相关；不能据此宣称存在已识别的固定延迟。差分跨两个位置时刻，也不应只挑最高相关值下结论。
- j1..3位置恒定，协议速度却恒为−0.00488472rad/s，说明存在固定非零读数/量化偏置迹象；对应差分相关系数因零方差而未定义，不记成“0相关”。
- j4/j5速度离散步长为0.024417877或0.024421692rad/s，两者微小差异符合浮点编码；近似固定量化栅格0.02442rad/s。中位数均为+0.012210846，不能将这直接当作需要补偿的机械参数。
- j4/j5速度互相关系数（零滞后）约0.001309，没有强同步串扰证据；恒定通道间的相关性无法判断。短窗口无法排除其它串扰路径。
- 检查前40阶自相关和去均值频谱，未见有力周期性跳变证据；j5最强频点仅占非DC总功率约2.08%，j4约2.15%。受窗口短、均匀时间假设和别名影响，不能认定周期源。

结合用户确认实体静止、位置仅量化抖动、积分不一致及j4相似行为，分类为“很可能是反馈噪声/量化”；不能证明硬件故障不存在。**没有修改机械臂参数。**

## C. 新只读规则、回放和重新采集

### 只读规则

本规则只决定停止读取，不控制机械臂、不代表机械臂控制安全认证；关闭接收器也不是急停。

| 级别 | 判据 | 用意 |
|---|---|---|
| Warning | 单个协议速度样本abs(v)>0.15 | 保留异常，避免用噪声尖峰冒充真实运动 |
| Abort | 同关节>0.15连续至少5帧且跨度≥19ms | 要求持续性；速度阈值未简单放大 |
| Abort | 相邻position跳变>0.02rad | 拦截不合理跳变/读数突变 |
| Abort | 相对首次position偏移>0.02rad | 停止明显姿态变化的采集 |
| Abort | 最近100ms内、覆盖至少50ms、净位移>0.01rad且至少3个同方向有效增量 | 区别连续位移与量化来回跳 |
| Abort | 同窗口位移>0.003rad、平均协议速度>0.05rad/s、方向一致且积分/位移比在0.25..4 | 要求速度与位置的物理一致性 |
| Abort | 初始2s无主动位置、位置断流>250ms、checksum/malformed、非有限数、I/O异常 | 不查询、不唤醒、不重连 |

监测前6物理候选槽位的运动量；index6的固定异常数值独立记录，不拿它的27.97rad/s冒充真实第七电机运动。完整原始7槽位仍记录并检查有限性。连续性规则使用主机接收时间；批量read中的多帧同时间不能当成精确设备时间。

旧记录回放：joint5 Warning=1，Abort=0。新增规则测试覆盖孤立尖峰、连续高速度、position跳变、速度/位移一致、量化抖动、NaN；连同协议/只读访问测试及全部七槽位保留测试共10项通过。代码见 `src/real_arm_readonly/real_arm_readonly/read_guard.py`。

## D. ROS、TF与RViz模型问题

**本轮未贯通六轴真实ROS→RViz。** 纯接收阶段完成后，因index5四项恒零而没有进入ROS发布阶段，随后关闭串口；没有给缺失的joint6伪造角度，也没有自动换成index6。

`/real_arm/raw_joint_states` publisher=0，subscriber=1（RSP）。因此实测ROS Hz和实际JointState样本均为N/A，不能拿200.87Hz串口频率冒充ROS频率。本轮没有把保存数据回放为“实时”消息。上一轮有界hz/echo查询同样没有样本；原链路的合成数据集成测试不算本轮真实贯通。

RSP/RViz仍是纯显示节点。`/real_arm/tf`有发布端但没有当前关节动态变换，RViz保持RobotModel Error/Global Warn。截图当前姿态不能用于实体比对。

关于“模型不正确”，已核查：

1. 从正在运行的RSP读取robot_description，与仓库 `config/arm6.urdf` 逐字一致；规范化文本SHA256为 `717659bac177f8e917fc248b33fb910879dd6f5f04b8198b03c42f6526a373db`。
2. 实际模型包含base_link+link1..6、joint1..6六个revolute，没有joint7，没有加载arm.urdf七轴或LL100模型。mesh全部指向A-L1-GAMMA资源；安装目录中的全部7个网格文件与源码逐字节一致。
3. 没有有效JointState导致动态TF缺失，这是当前显示不可信的已确认问题；**不把它等同于“CAD几何一定正确”**。实体外形、工具、安装方向与模型的差异仍需要现场描述；已询问外形问题还是姿态问题，尚未获得具体回复。
4. 未修改URDF、mesh、joint origin、符号或zero offset去凑外观。历史偏置仍不使用。底座坐标/视角差异与关节零位差异需要分别核对，不能仅凭当前错误状态截图诊断。

第六轴四项全零是本轮六轴可信可视化的明确缺口，不能通过GUI拖动或向全局/joint_states发假数据消除它。
