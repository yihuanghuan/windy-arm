## 2. 参数原理

### 2.1 零位 `zero_offset`

编码器角度与 URDF/Pinocchio 模型角度的关系：

```text
q_model = q_encoder + q0
```

后续 FK、Jacobian、gravity、RNEA、Vicon 外参都必须使用 `q_model`。所以零位标定回答的是：

```text
编码器读到某个角度时，模型里真正应该用哪个角度？
```

### 2.2 重力比例 `first_moment_ratio`

Phase3 单关节扫掠，把实测力矩和模型力矩都拟合成：

```text
tau(q) = A * sin(q - phi) + b
```

两条曲线对比：

```text
zero_offset        = -wrap(phi_measured - phi_model)
first_moment_ratio = A_measured / A_model
```

`ratio` 修正的是质量和质心距造成的重力幅值误差，不是固定力矩。运行时仍由模型按当前姿态实时计算重力。

### 2.3 摩擦

Phase2 用 breakaway torque 测静摩擦。当前控制链支持方向摩擦：

```text
kinetic_friction_pos_nm
kinetic_friction_neg_nm
```

实现位置：`task_space_smc/core/friction_feedforward.py`

实际形式：

```text
drive = qdot_ref + error_gain * position_error
tau_f = scale * F_direction * tanh(drive / velocity_epsilon)
```

`whole_task_smc_ros_runner.py` 会优先读取 `kinetic_friction_pos_nm/neg_nm`；没有方向参数时才退回 scalar `kinetic_friction_nm` 或 `stiction_nm`。

### 2.4 惯量 / armature

Phase5 通过力矩脉冲辨识等效惯量：

```text
qdd = (tau_extra - friction) / M
M = 1 / slope
```

`task_space_smc/core/model.py` 会把 `armature_kgm2` 加到 Pinocchio 模型关节侧惯量对角项。惯量只有在重复测试中符号、量级、离散度稳定时才写 candidate。

### 2.5 LESO

现有实现：

```text
task_space_smc/core/leso.py
task_space_smc/core/state_estimator.py
```

三阶状态含义：

```text
z1 = q_hat
z2 = qdot_hat
z3 = disturbance_hat
```

J5 的具体实验用法、RNEA residual 和验收数据见第 7 节；本项目当前只记录 J5 的
`z3` 做诊断，不把它直接加到 MotorControl。

## 7. J5 特例：LESO 辅助观测 + RNEA residual 动态辨识

它解决什么：

J5 原 Phase3 的重力信号弱，zero 容易被摩擦、回差和动态误差拉偏。因此这里不把
LESO 误解成“直接算出补偿参数的黑盒”，而是用它提供平滑的状态和总扰动观测，再用
RNEA 的物理模型残差辨识 J5 的四个工程参数：`q0`、`gravity ratio`、`F+`、`F-`。

代码入口：

```text
task_space_smc/hw/phase3_j5_leso_observer_tune.py
task_space_smc/core/state_estimator.py
task_space_smc/core/leso.py
```

LESO 的状态是三阶双积分链：

```text
z1 = q_hat
z2 = qdot_hat
z3 = disturbance_hat
```

常见的闭环扰动观测器会把 `z3` 直接加回控制器。例如模型预测需要 12 Nm，而真实系统
因摩擦和外扰需要 15 Nm，观测器估计 3 Nm 后在线补回 3 Nm。本实验不是这种用法：
当前只有 J5 启用 LESO，其他关节仍用 motor feedback；J5 的 `z3` 只记录和诊断，
不会直接加到 `MotorControl`，也不会直接输出 `q0/ratio/F+/F-`。

实验和数据链：

```text
冻结 J1/J2/J3 已确认参数，J4/J6 不作为辨识对象
  -> 多个安全上游姿态
  -> J5: -0.7 -> +0.7 rad，再 +0.7 -> -0.7 rad
  -> 记录 q, effort, LESO z1/z2/z3
  -> 对实际 q 平滑/求导得到 qdot, qddot
  -> fit_j5 只优化 q0, gravity ratio, F+, F-
```

每个真实采样点的模型计算为：

```text
q_model = q_encoder + q0
tau_rnea = RNEA(q_model, qdot, qddot)
tau_pred = (tau_rnea - gravity(q_model)) + ratio * gravity(q_model)
tau_pred[J5] += (F+ if qdot[J5] >= 0 else F-) * tanh(qdot[J5] / eps)
residual = tau_pred[J5] - tau_meas[J5]
```

其中 `tau_meas` 来自 `/joint_states.effort`。`zero` 主要改变动力学曲线沿关节角的
位置/相位，`ratio` 主要改变重力项幅值，正反运动产生的方向切换用于区分 `F+` 和
`F-`；多个上游姿态用于避免 zero 与 ratio 在单一局部姿态互相代偿。程序用
`scipy.optimize.least_squares` 对所有姿态、方向和时间点的 residual 一起拟合。

怎么判断可信：

不能只看 optimizer success。必须从同一 candidate 初值独立重复 3 次，不能继承上次拟合：

```text
run1: zero=-2.5637 deg, ratio=0.88196, F+=0.08538 Nm, F-=0.04141 Nm
run2: zero=-2.6667 deg, ratio=0.85770, F+=0.08032 Nm, F-=0.03836 Nm
run3: zero=-2.0700 deg, ratio=0.87710, F+=0.08445 Nm, F-=0.03797 Nm

zero span=0.5967 deg     ratio CV=1.47%
F+ CV=3.22%              F- CV=4.81%
tracking RMS CV=1.53%
```

因此 candidate 采用三次结果的工程平均值：

```text
zero_offset_deg      = -2.4335
first_moment_ratio   = 0.87225
kinetic_friction_pos = 0.08338 Nm
kinetic_friction_neg = 0.03925 Nm
```

这表示参数在当前机械臂、当前温度和当前实验流程下重复有效，不等于每个参数都是
脱离摩擦、回差和模型误差后的绝对物理真值。

### 10.1 外参、残差与坐标检查

它解决什么：

`T_arm_base_to_base_link` 和 `T_link6_to_arm_ee` 是待标的几何变换，不是 RMS 本身。
外参标定的验收对象是整条链：candidate zero、URDF/FK、Vicon 刚体定义和外参共同
能否解释多个真实姿态。每个姿态先消掉 Vicon 世界系：

```text
T_meas = inverse(T_W_arm_base) · T_W_arm_ee
T_pred = T_arm_base_to_base_link · FK(q_encoder + q0) · T_link6_to_arm_ee
```

位置残差是：

```text
e_p = p_pred - p_meas
position RMS = sqrt(mean(||e_p,i||²))
```

姿态不能直接相减四元数，而应先求相对旋转：

```text
R_err,i = R_pred,iᵀ · R_meas,i
e_R,i = angle(R_err,i)
orientation RMS = sqrt(mean(e_R,i²))
```

因此 position/orientation RMS 不是新旧外参参数之间的差值，而是这组参数放入
`candidate zero + URDF/FK + Vicon` 整条几何链后，在所有实机姿态上的最终拟合成绩。
RMS 越小表示 Vicon 测量和机器人模型越一致，但残差同时包含 zero、URDF 几何、
刚体原点/局部轴、marker 外参、回差和同步误差；例如 `position RMS=11.6 mm` 不等于
“base 外参错了 11.6 mm”。

本次 16 点数据的结果说明了这个区别：

```text
EE=link6 假设：          position RMS=22.883 mm, orientation RMS=74.030 deg
发现 link6->arm_ee 固定旋转：orientation RMS 约降到 4 deg
联合拟合 base 与 EE 外参：position RMS=11.614 mm, orientation RMS=6.699 deg
```

最后一组仍是 `diagnostic_only`：position RMS 高于 10 mm 验收线，且参数 Jacobian
condition number 约 `2863`，说明 base/EE 两组外参存在明显耦合，未写入正式
`vicon_extrinsics.yaml`。

实验和判断顺序：

1. 检查 `/vrpn/arm_base/pose`、`/vrpn/arm_ee/pose`、`/joint_states` 的帧数、静态 spread、源时钟间隔。
2. 用同一 candidate zero 计算 `T_meas` 与 `T_pred` 的位置和相对旋转残差。
3. 若相对变换正常而世界坐标数值整体改变，说明只是 Vicon world frame 变化，应做轴转换，不重标 zero 或外参。
4. 若相对变换仍失效，再查 `arm_base/arm_ee` 的刚体原点、局部轴、marker 组成和名称。

本次已确认旧数据为 `Y-up`，后续一轮数据为 `Z-up`。两套数据不能直接混用；后续控制和外参验收必须先固定同一套 Vicon 轴约定。

输出含义：

```text
arm_base rigid body frame -> robot base_link
```

对应文件：

```text
task_space_smc/config/vicon_extrinsics.yaml
```

验收：

- 外参是待标参数，position/orientation RMS 是验收指标；
- 位置 RMS、最大位置误差、姿态 RMS、最大姿态误差都要记录；
- 位置 RMS 应低于 10 mm，且 Jacobian 不能表现出严重的 base/EE 参数耦合；
- residual 大时优先查坐标轴、刚体原点、marker 外参、candidate zero、同步和丢帧；
- 未通过验收不得覆盖旧 `vicon_extrinsics.yaml`。

## 14. 常见问题

`/joint_states.effort` 全零：

- 检查 `arm_type:=a_l1`；
- 检查 `enable_direct_effort_command:=true`；
- 检查 USB 是否接入虚拟机；
- 检查是否 source 到旧 workspace。

Phase3 zero 漂移：

- 先查机械连接松动；
- 保持每次上电初始姿态一致；
- 记录 warmup 是否改变历史状态；
- 看关节温度是否升高；
- 看 `A/stiction` 是否过低。

J4/J5 Phase3 不通过：

- 不一定是算法错误；
- 后方质量小导致重力信号弱；
- `resid/A` 高、`A/stiction` 低时应判定不可辨识，不要硬写 zero。

Phase5 负摩擦：

- 检查脉冲是否突破静摩擦；
- 检查 `qdd` 质量；
- 检查 effort 与 qdd 时间对齐；
- 正反方向分开看。

Vicon residual 大：

- 检查 `arm_base` 刚体原点；
- 检查 `arm_base` / `arm_ee` 坐标轴；
- 检查末端 marker 是否和 link6 / 控制点重合；
- 检查 Vicon 丢帧和时间同步；
- 确认外参标定使用的是已校正 zero。
